# 股票分析全流程技术报告

> 分析基准：`app/services/analysis_service.py` → `tradingagents/` 模块  
> 报告日期：2026-05-16

---

## 一、总体架构

本项目采用"多智能体协作 + LangGraph 状态图"架构，将一次股票分析拆解为：

```
前端请求
  → FastAPI 路由层
    → 服务层（配置构建 + 任务管理）
      → TradingAgentsGraph（LangGraph 编排）
        → 分析师团队（采集数据 + 撰写报告）
          → 研究员团队（多头/空头辩论）
            → 交易员（生成方案）
              → 风险管理团队（三方讨论）
                → 信号处理器（结构化输出）
```

---

## 二、入口：HTTP 请求到任务创建

### 2.1 前端调用

前端在「股票分析」页面填写股票代码后，调用：

```
POST /api/analysis/single
Body: { symbol, parameters: { selectedAnalysts, researchDepth, ... } }
```

### 2.2 路由层（`app/routers/analysis.py`）

`submit_single_analysis()` 执行以下步骤：

1. 调用 `get_simple_analysis_service()` 获取服务单例
2. 调用 `analysis_service.create_analysis_task(user_id, request)` 在 MongoDB 写入任务记录（status=`pending`）
3. 通过 FastAPI **BackgroundTasks** 异步启动 `execute_analysis_background(task_id, user_id, request)`
4. **立即返回** `{ task_id, status: "pending" }` 给前端（不阻塞接口）

## 三、服务层：配置构建与任务调度

### 3.1 `AnalysisService`（`app/services/analysis_service.py`）

**核心流程（`_execute_analysis_sync_with_progress`）：**

| 步骤 | 操作 |
|------|------|
| 1 | 从 MongoDB `system_configs` 表读取活跃的系统配置，获取 `quick_model` / `deep_model` 的参数（max_tokens、temperature、timeout、api_base 等） |
| 2 | 调用 `create_analysis_config()` 组装完整的 `config` 字典（见 §3.2） |
| 3 | 调用 `_get_trading_graph(config)` 获取/创建 `TradingAgentsGraph` 实例（带本地内存缓存） |
| 4 | 调用 `trading_graph.propagate(symbol, analysis_date, progress_callback)` 执行分析 |
| 5 | 将返回的 `decision` 包装为 `AnalysisResult` 对象 |
| 6 | 写回 MongoDB、更新 Redis 进度、记录 Token 用量 |

**进度跟踪：** 通过 `RedisProgressTracker` 将每个节点的执行状态推送到 Redis，前端通过 WebSocket 或轮询读取。

### 3.2 `create_analysis_config()`（`app/services/simple_analysis_service.py`）

以 `DEFAULT_CONFIG` 为基础，按研究深度覆盖关键参数：

| 研究深度 | 辩论轮次 | 风险讨论轮次 | 记忆 |
|---------|---------|------------|------|
| 快速（1级）| 1 | 1 | 关闭 |
| 基础（2级）| 1 | 1 | 开启 |
| 标准（3级，推荐）| 1 | 2 | 开启 |
| 深度（4级）| 2 | 2 | 开启 |
| 全面（5级）| 3 | 3 | 开启 |

最终 `config` 还包含：`llm_provider`、`deep_think_llm`、`quick_think_llm`、`quick_model_config`（max_tokens/temperature/timeout）、`deep_model_config`、`backend_url`、`quick_api_key`/`deep_api_key` 等。

## 四、TradingAgentsGraph 初始化

类位于 `tradingagents/graph/trading_graph.py`。

**构造器做的事情：**

### 4.1 创建 LLM 实例（`quick_thinking_llm` + `deep_thinking_llm`）

- 全面支持多供应商：阿里百炼（DashScope）、DeepSeek、OpenAI、Anthropic、Google Gemini、SiliconFlow、OpenRouter、智谱 AI、百度千帆、GitHub Copilot 等
- API Key 优先级：**数据库配置 > 环境变量**
- 若 `quick_provider ≠ deep_provider`，进入「混合模式」，两个模型各自独立初始化

### 4.2 创建 Toolkit

`agents/utils/agent_utils.Toolkit` 封装所有数据获取函数（市场数据、情绪数据、新闻、基本面等统一接口）。

### 4.3 初始化记忆（ChromaDB 向量存储，配置允许时）

五种记忆实例：

| 记忆名称 | 用途 |
|---------|------|
| `bull_memory` | 看涨历史经验 |
| `bear_memory` | 看跌历史经验 |
| `trader_memory` | 交易员历史决策 |
| `invest_judge_memory` | 研究经理历史判断 |
| `risk_manager_memory` | 风险经理历史决策 |

### 4.4 创建 ToolNode 并编译 LangGraph 状态图

调用 `GraphSetup.setup_graph(selected_analysts)` 完成图的节点注册和边连接，最终 `workflow.compile()` 得到可执行图对象。

## 五、LangGraph 状态图结构

### 5.1 全局状态（`AgentState`）

```python
AgentState = {
    messages,                # LangChain 消息列表（流经各节点）
    company_of_interest,     # 股票代码
    trade_date,              # 分析日期
    market_report,           # 市场技术分析报告（字符串）
    sentiment_report,        # 社交情绪报告（字符串）
    news_report,             # 新闻报告（字符串）
    fundamentals_report,     # 基本面报告（字符串）
    investment_debate_state, # 多头/空头辩论状态（含轮次计数 count）
    investment_plan,         # 研究经理综合方案（字符串）
    trader_investment_plan,  # 交易员决策方案（字符串）
    risk_debate_state,       # 风险讨论状态（含轮次计数 count）
    final_trade_decision,    # 最终交易决策（文本，待结构化解析）
}
```

### 5.2 节点执行顺序（有向图）

```
START
  │
  ▼ [按 selected_analysts 顺序，串行执行]
  ┌──────────────────────────────────────────────────────────┐
  │  Market Analyst ──────┬─→ tools_market（执行工具）        │
  │                       └─→ Msg Clear Market（清理消息）──┐ │
  │                                                         │ │
  │  Fundamentals Analyst ┬─→ tools_fundamentals            │ │
  │                       └─→ Msg Clear Fundamentals ───────┤ │
  │                                                         │ │
  │  (可选) News Analyst ─┬─→ tools_news                    │ │
  │                       └─→ Msg Clear News ───────────────┤ │
  │                                                         │ │
  │  (可选) Social Analyst┬─→ tools_social                   │ │
  │                       └─→ Msg Clear Social ──────────────┘ │
  └──────────────────────────────────────────────────────────┘
  │
  ▼ [投资研究辩论，轮次由 max_debate_rounds 控制]
  Bull Researcher ◄──────────────────────► Bear Researcher
              └────── (达到轮次上限 2×N) ────┘
                              │
                              ▼
                     Research Manager（综合评判，使用 deep_thinking_llm）
                              │
                              ▼
                           Trader（生成交易计划，使用 quick_thinking_llm）
                              │
  ▼ [风险评估讨论，轮次由 max_risk_discuss_rounds 控制]
  Risky Analyst → Safe Analyst → Neutral Analyst → (循环 3×N 次) → Risk Judge
                                                                        │
                                                                        ▼
                                                                      END
```

## 六、各节点详解

### 6.1 分析师节点（Analyst Nodes）

**代表节点：** `Market Analyst`（`market_analyst.py`）、`Fundamentals Analyst`（`fundamentals_analyst.py`）等

**工作机制（"ReAct 循环"）：**

```
进入分析师节点
  │
  检查 state.messages 中是否已有 ToolMessage（工具结果）
  │
  ├── 没有工具结果 → LLM（绑定工具）决定调用哪些工具
  │       │
  │       LLM 返回 AIMessage（含 tool_calls）
  │       │
  │       conditional_logic.should_continue_xxx()
  │         ├── tool_calls 非空 且未超限 → 跳转到 tools_xxx 节点执行工具
  │         │       工具执行完毕（ToolMessage）→ 返回分析师节点
  │         └── tool_call_count ≥ 上限 → 强制跳 Msg Clear（防死循环）
  │
  └── 有工具结果 → LLM 基于真实数据撰写完整分析报告
          │
          更新 state.market_report（或对应报告字段）
          │
          conditional_logic：报告长度 > 100 字符 → 跳转 Msg Clear
```

**各分析师使用的统一工具（自动识别 A股/港股/美股）：**

| 分析师 | 主工具 | 数据内容 |
|--------|--------|---------|
| 市场分析师 | `get_stock_market_data_unified` | K线、技术指标（MA/MACD/RSI/BOLL）、成交量 |
| 基本面分析师 | `get_stock_fundamentals_unified` | PE/PB/PEG、财务数据、估值区间 |
| 新闻分析师 | `get_stock_news_unified` | 行业新闻、公告、宏观事件 |
| 社交分析师 | `get_stock_sentiment_unified` | 舆情数据、投资者情绪指数 |

**Msg Clear 节点的作用：** 清除 `messages` 列表（防止 token 溢出），将报告文本保留在 state 字段中传递给后续节点。

**防死循环机制：**
- 每类分析师有独立的工具调用计数器（`market_tool_call_count` 等）
- 市场/新闻/社交分析师：上限 **3 次**；基本面分析师：上限 **1 次**
- 超限后 `conditional_logic` 强制路由到 Msg Clear，跳出循环

### 6.2 研究员辩论（Bull / Bear Researchers）

- **Bull Researcher（看涨）**：基于四份分析报告，从利好角度论证买入理由；参考 `bull_memory` 历史经验
- **Bear Researcher（看跌）**：从风险角度论证谨慎理由；参考 `bear_memory` 历史经验
- **辩论轮次控制**（`ConditionalLogic.should_continue_debate`）：
  - `investment_debate_state.count < 2 × max_debate_rounds` → 交替发言（Bull → Bear → Bull → ...）
  - `count >= 2 × max_debate_rounds` → 跳转到 Research Manager

### 6.3 研究经理（Research Manager）

- 使用 **`deep_thinking_llm`**（高质量、高 token 上限模型）
- 综合多头/空头辩论历史 + 四份分析报告
- 输出 `investment_plan`（综合投资计划文本）
- 读取 `invest_judge_memory` 历史判断经验

### 6.4 交易员（Trader）

- 将 `investment_plan` 转化为具体的操作计划，输出 `trader_investment_plan`
- 明确买入/持有/卖出建议，附带仓位和时机建议
- 参考 `trader_memory` 历史交易经验

### 6.5 风险管理三辩手

| 角色 | 立场 | 关注点 |
|------|------|--------|
| Risky Analyst（激进派） | 积极进取 | 收益机会最大化 |
| Safe Analyst（保守派） | 风险规避 | 下行风险、止损位 |
| Neutral Analyst（中立派） | 综合平衡 | 风险收益比 |

- 轮次顺序：`Risky → Safe → Neutral → Risky → ...`
- 循环 `3 × max_risk_discuss_rounds` 次后终止，跳转 Risk Judge

### 6.6 风险经理（Risk Judge）

- 使用 **`deep_thinking_llm`**
- 综合三方风险讨论意见，输出 `final_trade_decision`（完整最终决策报告文本）
- 读取/更新 `risk_manager_memory`
- 执行完毕后图流程到达 END

## 七、结果处理：信号处理器

`SignalProcessor.process_signal()` 位于 `tradingagents/graph/signal_processing.py`。

**输入：** `final_trade_decision`（长文本，完整的交易决策报告）

**处理步骤：**

1. 识别股票市场类型（A股/港股/美股），确定货币单位（人民币/港币/美元）
2. 调用 `quick_thinking_llm`，提示词要求将报告解析为结构化 JSON
3. 多级价格提取（当 JSON 中 target_price 为空时）：
   - 正则匹配多种价格表达式（"目标价位: 45.50"、"¥45.50"、"45.50元" 等）
   - 智能推算（结合当前价格 + 涨跌幅信息）

**输出（结构化 `decision` 字典）：**

```json
{
  "action": "买入",
  "target_price": 45.50,
  "confidence": 0.75,
  "risk_score": 0.4,
  "reasoning": "基本面稳健，技术面突破，看多中期...",
  "model_info": "ChatDashScopeOpenAI:qwen-max",
  "summary": "...",
  "recommendation": "...",
  "key_points": ["...", "..."]
}
```

## 九、关键设计说明

| 设计点 | 详细说明 |
|--------|---------|
| **防死循环** | 每类分析师有独立工具调用计数器（市场/新闻/社交上限 3 次，基本面上限 1 次），超限强制跳出 |
| **消息清理** | 每个分析师完成后通过 Msg Clear 节点清空 `messages` 列表，避免长上下文 token 溢出 |
| **实例缓存** | `_trading_graph_cache` 对相同配置 hash 的 `TradingAgentsGraph` 实例做内存缓存，避免重复初始化 |
| **双模型策略** | `quick_thinking_llm` 用于分析师和交易员（速度优先），`deep_thinking_llm` 用于研究经理和风险经理（质量优先） |
| **统一工具接口** | 所有数据获取统一走 `get_stock_xxx_unified`，内部自动判断 A股/港股/美股 并调用对应数据源 |
| **混合厂家支持** | `quick_provider ≠ deep_provider` 时自动进入混合模式，两个 LLM 分别独立初始化 |
| **进度实时推送** | 每个 LangGraph 节点完成后通过 `_send_progress_update()` 触发 `progress_callback`，更新 Redis，前端实时展示 |
| **记忆反思机制** | 分析完成后可调用 `reflect_and_remember(returns_losses)` 将本次决策效果写入 ChromaDB，优化未来分析 |
| **异步非阻塞** | 分析任务在 `ThreadPoolExecutor` 中执行同步代码，不阻塞 FastAPI 事件循环 |
