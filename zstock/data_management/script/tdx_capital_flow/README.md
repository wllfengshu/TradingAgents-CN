# 通达信 pkg 资金流文件解析报告

## 一、已确认的文件结构

### 文件头 (12 字节)
```c
uint32 num_stocks;   // 逻辑证券数 (老包=4604, 新包=4619)
uint32 num_days;     // 最大天数 (通常=6000)
uint32 data_offset;  // 数据区起始偏移 (老包=84176, 新包=87991)
```

### 索引表 (从 offset 3068 开始, 每条 3072 字节)
```
+0:    uint32  prev_code    // 前一条代码 (链表)
+4:    char[8] stock_code   // ASCII 代码 (null 填充, 如 "600519\0\0")
+12:   char[8] reserved     // 全零
+20:   uint32  num_days     // 实际有数据的天数 (~464-469)
+24:   uint32  num_fields   // 字段数 (旧=18, 新=19)
+28:   uint32[] field_values // num_fields 个偏移/索引值
```

### 数据区 (从 ~18MB 开始)
- 按 **3072 字节/槽位** 组织
- 每槽包含 **13 个交易日** × **236 字节/天**
- 同一板块/股票的连续 13 天数据集中在一个槽位
- 日期从 20240801 到 20260710 (共 469 个交易日)

## 三、关键发现

1. **数据区起始位置**: 通过扫描日期模式 (20240801) 定位, 约在 18MB 处
2. **槽位大小**: 3072 字节, 含 13 天 × 236B 日线 + 4B 尾部
3. **板块按时间窗口排列**: 同一槽位的 13 天覆盖同一板块
4. **代码类型**: 880xxx (通达信板块), 600xxx (沪市个股), 000xxx (深市指数/个股), 399xxx (深市指数)
5. **板块与个股字段差异**: 个股有成交量(+4)/成交额(+8)/价格(+104,+108), 板块可能是不同含义

### 未确认字段 — 与东方财富 API 无法简单映射
对比了 7489 条 MongoDB (东方财富) 资金流数据与 TDX 字段：
- TDX +76/+88/+92/+96/+100 与 MongoDB 的 main/super_large/large/medium/small_inflow **无固定比例关系**
- TDX 字段之间: +88 ≈ +96 (大资金类), +92 ≈ +100 (小资金类), 但具体映射不明
- **可能原因**: 通达信和东方财富对"超大/大/中/小单"的分类阈值不同
