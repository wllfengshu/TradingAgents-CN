# 📘 「趋势 + 龙头 + 合力」截面日频策略 · 最终开发指南

> 适用：国金 miniQMT / A 股主板-only / 日频截面轮换  
> 作者语境：CFA 量化策略师规格书，可直接交付开发

## 一、策略定位（物种锁定）

| 维度 | 设定 |
|---|---|
| 市场 | A 股主板 only：沪 `60xxxx`（600/601/602/603/605）、深 `000/001/002/003`。剔 `300`（创业）、`688`（科创）、`8xxxx`（北交）、`4xxxx`（北交老）、一切 `ST/*ST` |
| 频率 | 日频截面。T 日收盘算分 → T+1 开盘集合竞价 / 开盘调仓 |
| 持仓 | 每日截面排序，买 top K，卖持有池中**跌出全主板后 20%** 的 + **触发 -8% 硬止损** 的 |
| 空仓规则 | 无主线日（RPS 分化 < 阈值）/ 候选池不足 → 不开新，旧仓继续按止损+淘汰管 |
| 物种 | 主线板块里挑上升通道中的龙头中军，日频轮换。**非打板、非抄底、非震荡市策略** |

## 二、系统架构

```
┌─────────────────────────────────────────────────────────┐
│ load_real_data()  ── 纯数据装载，不做任何衍生计算        │
│                                                         │
│  输入：query_service (MongoDB)                          │
│  输出（9个字段，全部原始数据）：                         │
│    trade_date, all_stocks, stock_infos,                 │
│    stock_ohlcv,          ← 个股 OHLCV DataFrame        │
│    stock_flow_recent,    ← 近5日资金流原始数据          │
│    sectors, sector_stocks,                              │
│    index_ohlcv, index_name                              │
│                                                         │
│  ※ 板块 OHLCV 聚合、涨停/连板、5d收益等衍生计算       │
│    已全部委托给因子类内部完成                           │
└──────────────────────┬──────────────────────────────────┘
                       │  **data 展开
                       ▼
┌─────────────────────────────────────────────────────────┐
│ run_pipeline()  ── 流程编排，所有计算委托因子类          │
│                                                         │
│  M1  MarketFactors    市场情绪（沪深300 OHLCV）         │
│  M2  SectorFactors    板块层（内部聚合板块OHLCV/资金流） │
│  M3  DragonFactors    龙头层（内部从OHLCV算5d收益/连板） │
│  M4+M5 ForceFactors   合力+最终合成（内部提取资金流指标）│
│  M6  最终选股 top K                                     │
│                                                         │
│  参数（9个）：                                          │
│    trade_date, all_stocks, stock_infos,                 │
│    stock_ohlcv, stock_flow_recent,                      │
│    sectors, sector_stocks,                              │
│    index_ohlcv, index_name                              │
└─────────────────────────────────────────────────────────┘
```

### 因子类职责一览

| 因子类 | 接收的原始数据 | 内部计算 | 输出 |
|--------|---------------|---------|------|
| `MarketFactors` | `index_ohlcv` (沪深300 OHLCV) | 5 个市场情绪子因子 (趋势/布林/量能/动量/波动率) | 市场等级 + 仓位缩放 |
| `SectorFactors` | `stock_ohlcv` + `stock_flow_recent` | 板块 OHLCV 聚合、资金流聚合、从 OHLCV 算涨停/连板 | `Dict[sector_code→float]` M2 得分 |
| `DragonFactors` | `stock_ohlcv` | 从 OHLCV 算 5d 收益、成交额、连板天数 | `Dict[stock_code→float]` M3 得分 |
| `ForceFactors` | `stock_flow_recent` + `stock_ohlcv` | 提取当日资金流、5d 净流入、流入天数、换手率 | 排序后候选列表（含 `final_score`） |

## 三、信号流水线

```
每日 T 收盘后：
│
├── M1.  市场情绪评估（MarketFactors）
│       输入：沪深300 指数 OHLCV
│       ├── MF1 趋势强度（20MA 斜率，30%）
│       ├── MF2 布林带位置（25%）
│       ├── MF3 量能状态（当日量/20日均量，20%）
│       ├── MF4 近期动量（5日涨跌幅，15%）
│       └── MF5 波动率压制（ATR/MA 比率倒数，10%）
│       → grade: green(≥70)/yellow(40~70)/red(<70)
│       → red 灯 → 禁止开新仓，管道终止
│       → yellow → position_scale=0.5（缩半仓）
│
├── M2.  板块计算（SectorFactors）
│       输入：stock_ohlcv + stock_flow_recent + sector_stocks
│       内部自动完成：
│       ├── 板块 OHLCV 聚合（等权收益率 + 量额求和）
│       ├── 板块资金流聚合（成分股当日主力净流入求和）
│       ├── 涨停标志（日涨幅 ≥ 9.5%）
│       └── 连板天数（从最新日往回数连续涨停）
│       因子：
│       ├── F2.1  板块 20 日 RPS
│       ├── F2.2  板块资金净流入
│       ├── F2.3  涨停浓度 = 涨停家数 / 成分数
│       ├── F2.4  连板高度 = 板块内最高连板天数
│       └── F2.5  成交占比斜率 = (板块成交/全板块) 的 5 日 MA 斜率
│       合成：5 因子 min-max 归一化 → 等权加总 → top 3 板块
│       前置：板块黑名单过滤（config/blacklist_sector.json）
│
├── M3.  龙头计算（DragonFactors）
│       输入：stock_ohlcv（过滤后）
│       内部自动完成：
│       ├── 5 日收益率
│       ├── 当日成交额
│       └── 连板天数（从 OHLCV 计算，阈值 9.5%）
│       因子：
│       ├── F3.1  超额收益：个股 5 日收益 - 板块中位数（20%）
│       ├── F3.2  人气：个股当日成交额（15%）
│       ├── F3.3  高度：连板天数（45%，核心特征）
│       └── F3.4  量价共振度：近5日"量价健康"天数占比（20%）
│       前置过滤（pipeline 编排）：
│       ├── M3.1 主板过滤（^(60|000|001|002|003) 剔创业/科创/北交）
│       ├── M3.2 个股黑名单（config/blacklist_stock.json）
│       └── M3.3 布林上升滤（BOLL(20,2) 中轨向上 + 价在中轨上）
│       每块取 top 2-3 → 合计 ≤ 6-9 候选
│
├── M4.  合力校验（ForceFactors）
│       输入：候选 {code, sector_code, dragon_score}
│             + stock_flow_recent + stock_ohlcv
│       内部自动提取：当日主力/散户净流入、总成交、5d流入天数、换手率
│       门槛：主力净流入 / 总成交 >= 3%
│       合力综合分（4 因子加权，候选集内 min-max 归一化）：
│       ├── F_coop1  主力净值比（35%）
│       ├── F_coop2  主散比（25%）
│       ├── F_coop3  净流入持续天数（25%）
│       └── F_coop4  换手质量（15%）
│       过不了淘汰；全灭 → 当日无新开信号
│
└── M5+M6. 最终得分 + 选股
       Score = 0.4×M2_板块rank + 0.35×M3_龙头分 + 0.25×M4_合力综合分
       全候选截面排序 → top K（初版 K=5，参数可调）
       每条信号注入 market_grade + position_scale 供策略层使用
```

## 四、关键因子公式与参数初值表

### 4.1 M1 市场情绪（MarketFactors，5 因子加权）

| 因子 | 权重 | 公式 | 参数 |
|------|------|------|------|
| MF1 趋势强度 | 30% | 20MA 斜率 → sigmoid 映射到 0~100 | MA(20), slope_window=5, k=800 |
| MF2 布林位置 | 25% | `(close - lower) / (upper - lower)` → ×100 | MA(20), σ=2 |
| MF3 量能状态 | 20% | `当日量 / 20日均量` → 折线映射 | MA(20) |
| MF4 近期动量 | 15% | 5 日涨跌幅 → sigmoid 映射 | window=5, k=30 |
| MF5 波动率压制 | 10% | `ATR(20) / MA(20)` 倒数 → 折线映射 | ATR(20), MA(20) |

风险等级：
- `green` [70, 100]：正常开仓，position_scale=1.0
- `yellow` [40, 70)：缩半仓，position_scale=0.5
- `red` [0, 40)：禁止开新仓，管道终止

### 4.2 M2 板块层（SectorFactors，5 因子等权）

> 所有衍生数据由 SectorFactors 内部从 `stock_ohlcv` + `stock_flow_recent` 计算：
> - 板块 OHLCV：成分股等权收益率聚合 close，量额求和
> - 涨停标志：日涨幅 ≥ 9.5%（`_LIMIT_UP_THRESHOLD`）
> - 连板天数：从最新日往回数连续 ≥9.5% 的天数

| 因子 | 公式 | 参数 | 备注 |
|---|---|---|---|
| F2.1 RPS | 板块聚合 close 的 20 日收益 → 全板块 rank | 窗口 20 日 | SectorFactors 内部聚合 |
| F2.2 净流入 | 成分股当日 `main_inflow` 求和 → 全板块 rank | 日频 | 从 `stock_flow_recent` 提取 |
| F2.3 涨停浓度 | `cnt_limit_up / cnt_members` | 阈值 9.5% | 从 OHLCV 计算 |
| F2.4 连板高度 | `max(连续封板天数)`，板块内 | 阈值 9.5% | 从 OHLCV 计算 |
| F2.5 成交占比斜率 | `(板块成交/全板块成交)` 的 5 日 MA → 线性回归斜率 | 5 日 | `np.polyfit` 一阶系数 |

合成：`Score_sector = mean(minmax(F2.1), minmax(F2.2), minmax(F2.3), minmax(F2.4), minmax(F2.5))`

### 4.3 M3 龙头层（DragonFactors，4 因子加权）

> 所有衍生数据由 DragonFactors 内部从 `stock_ohlcv` 计算：
> - 5 日收益率：`(close[-1] - close[-6]) / close[-6]`
> - 成交额：OHLCV 最后一行 `amount`
> - 连板天数：从 OHLCV 往回数连续涨停

| 因子 | 权重 | 公式 | 备注 |
|---|---|---|---|
| F3.1 超额收益 | 20% | `个股5日收益 - 板块中位数`，板块内 rank | 中位数替代均值，避免极端票拉偏 |
| F3.2 人气 | 15% | `个股当日成交额`，板块内 rank | 降权，避免与合力层重复 |
| F3.3 高度 | **45%** | `连板天数`，板块内 rank | 真龙头核心特征，权重最高 |
| F3.4 量价共振 | 20% | 近5日"量价健康"天数 / 5，板块内 rank | 价涨量涨 OR 价跌量缩 OR 涨停日 |

合成：`Score_dragon = 0.20×F3.1 + 0.15×F3.2 + 0.45×F3.3 + 0.20×F3.4`

### 4.4 M4 合力层（ForceFactors，净值比门槛 + 4因子评分）

> 资金流指标由 ForceFactors 内部从 `stock_flow_recent` + `stock_ohlcv` 提取：
> - 当日主力/散户净流入、总成交：取 `stock_flow_recent[code][-1]`
> - 5 日净流入天数：统计 `stock_flow_recent[code]` 中 `main_inflow > 0` 的天数
> - 换手率：取 OHLCV 最后一行 `turnover` / `turnover_rate` 字段

**过滤门槛：**
```
主力净流入 / 总成交 >= 3%
```

**合力综合分（通过门槛后的评分）：**

| 子因子 | 权重 | 公式 | 备注 |
|---|---|---|---|
| F_coop1 主力净值比 | 35% | `主力净流入 / 总成交`，候选集 rank | 合力核心强度 |
| F_coop2 主散比 | 25% | `主力 / (主力 + \|散户\|)`，候选集 rank | 统一映射到 (0, 1] |
| F_coop3 持续天数 | 25% | `近5日内主力净流入>0的天数`，候选集 rank | 连续流入代表真实意图 |
| F_coop4 换手质量 | 15% | 换手率映射到 0~1（5%~20% 为满分区间） | 活跃但不过热 |

**F_coop2 主散比（统一公式）：**

```
main_retail_ratio = main_flow / max(main_flow + abs(retail_flow), 1e-8)
```

| 散户行为 | 取值范围 | 量化含义 |
|---|---|---|
| `retail > 0` 同向 | (0, 0.5) | 散户跟风，主力占比越高比值越高 |
| `retail == 0` 纯机构 | =1.0 | 完全无散户参与 |
| `retail < 0` 背离 | (0.5, 1.0] | 主力接盘散户筹码，>0.5 表示主力强于散户抛压 |

> 统一公式消除了旧三档分支的跳跃不连续性，同时保留了"散户背离时主力接盘"的高质量信号（ratio > 0.5）。

换手率质量映射：
- `< 3%`：0.1（冷盘）
- `3%~5%`：线性升至 1.0
- `5%~20%`：1.0（优质区间）
- `20%~30%`：线性降至 0.1
- `> 30%`：0.1（过热）

合力综合分 = `0.35×coop1 + 0.25×coop2 + 0.25×coop3 + 0.15×coop4`（各子因子在候选集内 min-max 归一化到 0-100）

### 4.5 M3.3 布林上升滤

| 参数 | 初值 | 可调 |
|---|---|---|
| 周期 | 20 | — |
| 标准差倍数 | 2 | — |
| slope_5 计算 | `(mid_t - mid_{t-5}) / mid_{t-5}` | — |
| 上升阈值 | `slope_5 > 0`（严）｜ 也可 `> +0.2%`（更严，回测对比） | 建议先 `> 0` |
| 价位置 | `close > mid`（必须，非可选） | — |

> 📌 为什么 `slope_5 > 0 & close > mid` 双条件：slope>0 保证中轨在抬，close>mid 保证价已站上中轨——两者缺一个都不是"上升趋势票"。

### 4.6 M5+M6 权重

```
w_sector = 0.4   # 板块是前提，没主线什么都白搭
w_dragon = 0.35  # 龙头是核心 α 来源
w_coop   = 0.25  # 合力是确认，权重最低
```

回测时可网格：`w_sector ∈ [0.3,0.4,0.5]`, `w_dragon ∈ [0.3,0.4,0.5]`, `w_coop ∈ [0.15,0.25,0.35]`，约束 sum=1。

## 五、各层职责边界（防止因子重复）

```
M3 龙头 = "这只票是板块里价格行为最强的吗？"
  → 超额收益、连板高度、量价共振、成交额（降权）
  → 全部是价格/量价信号，不碰资金流向
  → 连板天数/5d收益从 OHLCV 计算，无需外部传入

M4 合力 = "真的有钱在推这只票吗？推的意图是买入还是出货？"
  → 主力净值比（净买入强度）
  → 主散比（机构主导 vs 散户追涨）
  → 净流入持续天数（单日 vs 多日意图）
  → 换手质量（活跃度健康程度）
  → 所有资金流指标从 stock_flow_recent 内部提取，pipeline 不预计算
```

> ⚠️ F3.2 成交额（M3）与 F_coop 资金流（M4）虽都涉及"交易量"，但维度不同：
> 成交额衡量市场关注度（量），资金流衡量买卖方向（净值）。两者不可替代，但 F3.2 已降权至 15% 以避免过度重叠。

## 七、黑名单 JSON Schema

### 7.1 板块黑名单 `config/blacklist_sector.json`

```json
{
  "sectors": [
    "*房地产*",
    "*光伏*",
    "*ST*",
    "*借壳*",
    "*退市*",
    "*贵金属*"
  ],
  "updated": "2026-06-27",
  "note": "光伏2024Q2集体暴雷暂避；地产长期无主线；ST及其他问题板块"
}
```

匹配逻辑：对国金概念板块名做 `fnmatch.fnmatch(name, pattern)`。

### 7.2 个股黑名单 `config/blacklist_stock.json`

支持两种格式（兼容）：

```json
{
  "stocks": [
    "000981.SZ",
    {
      "code": "600XXX.SH",
      "reason": "2025-03 立案调查",
      "until": "2026-12-31"
    }
  ],
  "updated": "2026-06-27"
}
```
