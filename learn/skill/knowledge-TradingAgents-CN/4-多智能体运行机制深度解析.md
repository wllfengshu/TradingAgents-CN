## 1. Agent的定义方式

每个 Agent 通过 **工厂函数（Factory Function）** 创建，返回一个 **节点函数（Node Function）**。

### 1.1 工厂函数模式

```python
# agents/analysts/market_analyst.py

def create_market_analyst(llm, toolkit):
    """工厂函数：创建市场分析师节点"""

    def market_analyst_node(state):
        """节点函数：实际执行分析的函数"""

        # 1. 从 state 提取输入数据
        ticker = state["company_of_interest"]
        current_date = state["trade_date"]
        tool_call_count = state.get("market_tool_call_count", 0)

        # 2. 构建提示词模板
        prompt = ChatPromptTemplate.from_messages([
            ("system", "你是一位专业的股票技术分析师..."),
            MessagesPlaceholder(variable_name="messages"),
        ])

        # 3. 绑定工具并调用 LLM
        tools = [toolkit.get_stock_market_data_unified]
        chain = prompt | llm.bind_tools(tools)
        result = chain.invoke({"messages": state["messages"]})

        # 4. 处理工具调用（如果有）
        if result.tool_calls:
            # 执行工具，获取数据
            # 再次调用 LLM 生成报告
            ...

        # 5. 返回更新的 state 字典
        return {
            "messages": [result],
            "market_report": report,
            "market_tool_call_count": tool_call_count + 1
        }

    return market_analyst_node
```

|-----------|---------|--------|---------|

| **基本面分析师** | `create_fundamentals_analyst(llm, toolkit)` | LLM + 工具包 | `agents/analysts/fundamentals_analyst.py` |

| **交易员** | `create_trader(llm, memory)` | LLM + ChromaDB | `agents/trader/trader.py` |

| **风险法官** | `create_risk_manager(llm, memory)` | LLM + ChromaDB | `agents/managers/risk_manager.py` |

### 1.3 核心设计特点

1. **工厂模式**：每个 Agent 都通过工厂函数创建，便于注入不同配置
2. **状态隔离**：每个节点函数接收 state，返回更新的字段，不直接修改全局状态
3. **工具绑定**：通过 `llm.bind_tools(tools)` 让 LLM 能够调用工具
4. **计数器机制**：每个分析师有独立的工具调用计数器，防止死循环

## 2. State状态管理

系统使用 **`AgentState`** 管理全流程状态，继承自 LangGraph 的 `MessagesState`。

### 2.1 主状态定义

```python
# agents/utils/agent_states.py

class AgentState(MessagesState):
    """主状态：贯穿整个分析流程"""

    # ===== 输入参数 =====
    company_of_interest: Annotated[str, "股票代码"]
    trade_date: Annotated[str, "分析日期"]
    sender: Annotated[str, "当前发言者"]

    # ===== 阶段1输出：分析报告 =====
    market_report: Annotated[str, "市场分析报告"]
    sentiment_report: Annotated[str, "社交媒体情绪报告"]
    news_report: Annotated[str, "新闻分析报告"]
    fundamentals_report: Annotated[str, "基本面分析报告"]

    # ===== 工具调用计数器（防死循环）=====
    market_tool_call_count: Annotated[int, "市场分析师工具调用计数"]
    news_tool_call_count: Annotated[int, "新闻分析师工具调用计数"]
    sentiment_tool_call_count: Annotated[int, "社交媒体分析师工具调用计数"]
    fundamentals_tool_call_count: Annotated[int, "基本面分析师工具调用计数"]

    # ===== 阶段2：投资辩论 =====
    investment_debate_state: Annotated[InvestDebateState, "投资辩论状态"]
    investment_plan: Annotated[str, "投资计划（研究经理输出）"]

    trader_investment_plan: Annotated[str, "交易执行计划"]
```

## 4. 条件路由逻辑

`ConditionalLogic` 类决定图的流向。

### 4.1 分析师路由

判断是否继续调用工具或结束分析：

```python
# graph/conditional_logic.py

def should_continue_market(self, state: AgentState):
    """市场分析师的条件路由"""

    messages = state["messages"]
    last_message = messages[-1]

    # 1. 检查工具调用次数上限（防死循环）
    tool_call_count = state.get("market_tool_call_count", 0)
    max_tool_calls = 3

    if tool_call_count >= max_tool_calls:
        return "Msg Clear Market"  # 强制结束

    # 2. 检查是否已有完整报告
    market_report = state.get("market_report", "")
    if market_report and len(market_report) > 100:
        return "Msg Clear Market"  # 分析完成，结束

    # 3. 检查是否有工具调用
    if hasattr(last_message, 'tool_calls') and last_message.tool_calls:
        return "tools_market"  # 去执行工具

    return "Msg Clear Market"  # 无工具调用，结束
```

**路由逻辑流程图**：

```
Market Analyst 执行
        │
        ▼
┌───────────────────────────┐
│ should_continue_market()  │
└───────────────────────────┘
        │
        ├── 工具调用次数 >= 3？
        │       │
        │       └── YES ──► "Msg Clear Market"（强制结束）
        │
        ├── 报告已存在且长度 > 100？
        │       │
        │       └── YES ──► "Msg Clear Market"（分析完成）
        │
        ├── 最后消息有 tool_calls？
        │       │
        │       ├── YES ──► "tools_market"（执行工具）
        │       │               │
        │       │               └── 执行后返回 Market Analyst
        │       │
        │       └── NO ──► "Msg Clear Market"（结束）
```

### 4.2 投资辩论路由

看涨/看跌交替发言：

```python
def should_continue_debate(self, state: AgentState) -> str:
    """投资辩论的条件路由"""

    current_count = state["investment_debate_state"]["count"]
    max_count = 2 * self.max_debate_rounds  # 每轮双方各发言一次
    current_speaker = state["investment_debate_state"]["current_response"]

    # 达到最大次数，结束辩论
    if current_count >= max_count:
        return "Research Manager"

    # 交替发言
    next_speaker = "Bear Researcher" if current_speaker.startswith("Bull") else "Bull Researcher"
    return next_speaker
```

**辩论轮次示意**（默认 `max_debate_rounds=1`）：

```
Bull Researcher (count=1)
        │
        ▼ should_continue_debate() -> count=1 < 2, 下一个是 Bear
        │
Bear Researcher (count=2)
        │
        ▼ should_continue_debate() -> count=2 >= 2, 结束
        │
Research Manager（综合裁决）
```

### 4.3 风险评估路由

激进→保守→中性循环发言：

```python
def should_continue_risk_analysis(self, state: AgentState) -> str:
    """风险评估的条件路由"""

    current_count = state["risk_debate_state"]["count"]
    max_count = 3 * self.max_risk_discuss_rounds  # 每轮三人各发言一次
    latest_speaker = state["risk_debate_state"]["latest_speaker"]

    # 达到最大次数，结束讨论
    if current_count >= max_count:
        return "Risk Judge"

    # 循环发言：Risky -> Safe -> Neutral -> Risky ...
    if latest_speaker.startswith("Risky"):
        return "Safe Analyst"
    elif latest_speaker.startswith("Safe"):
        return "Neutral Analyst"
    else:
        return "Risky Analyst"
```

**风险讨论轮次示意**（默认 `max_risk_discuss_rounds=1`）：

```
Risky Analyst (count=1)
        │
        ▼ -> Safe Analyst
        │
Safe Analyst (count=2)
        │
        ▼ -> Neutral Analyst
        │
Neutral Analyst (count=3)
        │
        ▼ -> count=3 >= 3, 结束
        │
Risk Judge（最终裁决）
```

## 6. 记忆系统

### 6.1 ChromaDB 向量记忆

基于 ChromaDB 的向量记忆，用于存储历史决策和反思结果：

```python
# agents/utils/memory.py

class FinancialSituationMemory:
    """金融场景记忆系统"""

    def __init__(self, name: str, config: Dict):
        self.collection_name = name
        self.embeddings = OpenAIEmbeddings()
        self.vectorstore = Chroma(
            collection_name=name,
            embedding_function=self.embeddings,
            persist_directory=config.get("memory_dir", "./memory")
        )

    def add_memory(self, situation: str, recommendation: str):
        """添加记忆"""
        self.vectorstore.add_texts(
            texts=[f"Situation: {situation}\nRecommendation: {recommendation}"],
            metadatas=[{"type": "reflection"}]
        )

    def get_memories(self, situation: str, n_matches: int = 2):
        """检索相关记忆"""
        return self.vectorstore.similarity_search(
            query=situation,
            k=n_matches
        )
```

```python
class Reflector:

    def reflect_bull_researcher(self, state, returns_losses, memory):
```

## 总结

TradingAgents-CN 的多智能体系统采用 **LangGraph 状态机** 编排，核心特点：

1. **工厂模式定义 Agent**：每个 Agent 通过工厂函数创建，便于配置注入
2. **TypedDict 定义 State**：强类型状态管理，字段含义清晰
3. **StateGraph 编排流程**：支持顺序边和条件边，灵活控制流程
4. **ConditionalLogic 路由**：基于状态内容动态决定下一步
5. **计数器防死循环**：每个分析师独立计数，确保流程终止
6. **ChromaDB 记忆系统**：存储历史经验，支持反思学习

这套架构清晰、可扩展性强，适合添加新的分析师、研究员或风险管理角色。
